## Invariants & contracts

- **Serialization is the crown jewel.** One state shape serves URLs, files, presets, snapshots (`buildPresetStateSkeleton` / `applyPresetState`, ~main.js:24784+). Never rename or restructure a persisted field without a versioned migration: bump `STATE_VERSION` and add a step to `src/state-migrations.js` (pure, tested with a real old file). `applyPresetState` and snapshot-slot loading run every state through `migrateState` first, so apply code only sees the current shape; a state with a higher `v` loads best-effort with a "saved by a newer version" banner. Snapshot-set files carry their own separate `v: 1` (container format, not yet versioned).
- `scripts/regression-smoke.mjs` (`npm run check:regression`) greps main.js for four literal source lines guarding past bug fixes. If a legit refactor breaks a guard, update the guard in the same commit and say so — don't delete it silently. Replace guards with real tests as Phase 1 lands.
- **Rendering goes through the display list.** Anything a page-layout export shows is built once by a `build…Scene` function in main.js (screen coordinates; see `src/scene/display-list.js` for primitives) and drawn by `paintDisplayList` (canvas) or `emitDisplayListSvg` (export, shifted by the page origin). Change the builder, never the painter or emitter, for a visual change. Interactive overlays (hover rings, selection, axis-edit handles, volume sliders, 3D shading) stay canvas-only in `draw()`. The export renders with `getStaticNodeEnv()` — no hover/playback/selection effects. Verify with the golden harness in `.claude/` (see memory): canvas must stay pixel-identical unless a change is deliberate. Ratio/spelling/HEJI math now lives in `src/lib/pitch.js` (shared by all three apps), including the ratio→pitch-class spelling walk `spellPitchClassFromAxisRatios` — change it there, never re-inline copies. `TRUE_SPELLING_INTERVALS` and `HEJI_RULES` are snapshot-tested; a deliberate change updates `tests/__snapshots__`. main.js's `getHejiAnnotation` (DOM-bound) is still local but consumes the shared rules/helpers.
- **Node identity:** every persisted per-node map is keyed by the stable address `grid:x,y,z` or `custom:x,y,z|slot` (`getSnapshotNodeKey`), never by runtime `node.id`. Readers still accept the pre-September-2026 forms (numeric spelling ids, `custom:<id>` distance keys) and rewrite them on load. Edge keys join two node keys with `|`; always split them with `parseDistanceEdgeKey`. Snapshot states keep empty collections as `[]` (`getPresetState({ keepEmptyCollections: true })`) so snapshot-set diffs can express deletions.
- **Keep the heavy chunks lazy.** `src/custom-oscillators.js` (the ~900 kB `web-audio-oscillators` wavetables) is reached only through dynamic `import()` (`ensureCustomOscillators` in main.js); `src/custom-oscillator-types.js` is the static-safe half (names + two small waves). main.js loads `src/interval-names.json` by `fetch` of the emitted asset (`loadIntervalNames`), never by import: a dynamic `import()` of the JSON makes rolldown wrap it in a runtime helper that lands in the main chunk, and overtones' static import of the same JSON then pulls the whole editor into the overtones page. The build output must show `index.html` preloading only `pitch`, `preload-helper`, and `custom-oscillator-types`.
- **Fonts:** every bundled font is OFL; `src/fonts/FONTS.md` is the manifest and must gain a row for any new font.
- **The document store (Phase 4.1, in progress on branch `store`).** `src/state/store.js`; in main.js `doc` is the live document and `store.set({ key })` the only way to change it. One subscriber (`bindDocumentReactions`) invalidates caches, syncs mirrored controls, redraws (`scheduleDraw`) and updates the URL — call sites must not. Values are replaced, never mutated in place (undo keeps old values by reference). Migrated so far: display options (Hz, ratio cents, cents deviation/sign, directional ratios, HEJI, enharmonics, cents/Hz precision); tuning (`doc.fundamental`, `doc.a4` — no longer read from their inputs; fundamental spelling, feature mode, spelling mode). Changes made before `bindDocumentReactions()` runs at startup are collected and replayed when it does. Undo history is recorded but Cmd+Z isn't wired to it until the slices cover the editor (decision: undo everywhere).
- State not yet in the store lives in module globals **and the DOM** (e.g. `fundamentalInput.value`). After mutating state, you must call `draw()` and usually `schedulePresetUrlUpdate()` — forgetting these is the house bug class.

## Rules

- Run `npm test` and `npm run check:regression` before committing. `npm run lint` is errors-only across the whole repo (extracted modules at full strictness; the three monoliths at an advisory tier where `no-undef` etc. still fail); `npm run lint:warn` adds the dead-code warnings.
- Never commit: `dist/`, `node_modules/`, `.venv*/`, `.DS_Store`, `.claude/projects/`.
- Push to `main` deploys to production immediately — don't push unverified work.
- Test changes against a saved Creator JSON round-trip (load → save → load) when touching serialization.
